# AGENTS.md

Instructions for coding agents working in this repo. Humans should read [CONTRIBUTING.md](CONTRIBUTING.md) first. This file isn't generated by `de-web-sdk sync`; the SDK writes managed blocks only in consumer repos.

## Commands

```sh
npm ci                 # install; lifecycle scripts are off in .npmrc
npm run build          # TypeScript project references, all packages
npm test               # node:test against the TypeScript sources
node --conditions=development --test packages/core/test/check.test.ts   # one file
OPENSPEC_TELEMETRY=0 npx -y @fission-ai/openspec@1.13.2 validate --all --strict
```

Run `npm test` and `npm run build` before you finish. Both must pass.

## Layout

- `packages/core`: the pack format, JSON Schemas in `schema/`, trust, composition, checks, and agent files. Other packages depend on it.
- `packages/cli`: the consumer CLI and the MCP server in `src/mcp/`
- `packages/pack`: the producer toolkit and the eval runner in `src/evals/`
- `packages/vscode`: the VS Code extension
- `openspec/`: the scope, and changes with their proposal, design, specs, and tasks
- `docs/`: the consumer and producer guides

## Code conventions

- TypeScript 7 with `erasableSyntaxOnly`: no enums, namespaces, or parameter properties. Relative imports end in `.ts`, which the build rewrites.
- Node.js built-ins only where possible. Add a dependency only with a stated reason, and pin security-sensitive ones exactly.
- The core library never writes to standard output, so the MCP server's protocol stream stays clean.
- CLI output is versioned: JSON output must match `packages/core/schema/output/`. Regenerate golden files with `UPDATE_GOLDEN=1 npm test` only when a change to output is intended.
- Match the surrounding code's comment density and naming. Comments explain why, not what.

## Tests

- Every behavior change gets a test that fails without the change. Check that it does, then restore the change.
- Tests use temporary directories from `packages/core/test/helpers.ts`, and never touch the developer's home directory. Environment overrides such as `DE_WEB_SDK_HOME` exist for that. Only the pnpm and Yarn setup tests reach a registry, and they skip when the tool is missing.

## Security invariants

Never weaken these without an explicit decision recorded in the design:

- Packs are verified, by provenance or signature and by file digests, before any of their code runs or any file is written.
- Check adapters run in a separate process with Node.js's permission model: read-only, no child processes, no workers, and a minimal environment.
- Skills and pack files are verified again each time they're served.
- Agent-facing commands use `npx --no`, so npx never downloads a package by name.
- Nothing sends feedback without an explicit submit call.

## Specs and docs

- Design changes go in the OpenSpec change's `design.md`, with the rejected alternative. Behavior goes in its `specs/`, written as observable results.
- Check off a task in `tasks.md` only after verifying it as the task states.
- Update the guides in `docs/` in the same change as the behavior they describe.
- Prose is American English: short sentences, active voice, and no filler.

## Don't

- Don't publish packages, push, or create releases unless asked.
- Don't commit generated output: `dist/`, `*.tsbuildinfo`, VSIX files, or eval caches.
